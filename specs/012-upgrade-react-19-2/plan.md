## Testing strategy
- Run the existing Jest suite unchanged: `npm test`. No new test files
  expected; if any snapshot or `@testing-library/react` behavior shifts
  because of internal React changes, fix the *test* only if it reflects an
  intentional behavior change in React 19.2, otherwise treat it as a
  regression to investigate before merging.
- Run `npm run lint` (uses `eslint-config-next`, unaffected by a react-only
  bump, but still gate on it since `@types/react` bumps can occasionally
  surface new type-aware lint findings).
- Run `npm run build` to confirm the static export still succeeds end to
  end (App Router pages compile against the new React version).
- Manual smoke test after `npm run dev`: navigate through `caixa`, `metas`,
  `patrimonio`, `emprestimos`, `relatorios`, `notas`; verify forms/modals
  still open/submit and charts render (exercises `general-chart.tsx`
  ApexCharts wrapper, which is sensitive to React version mismatches).
- Verify the PWA/offline flow still works (`src/app/offline`,
  `service-worker/app-worker.ts`) since Serwist wraps the Next build.

## Rollout / risk mitigation
1. Bump `react`/`react-dom`/`@types/*` first, in isolation, before touching
   Next.js (spec 013) — this keeps the change set small and easy to bisect
   if something regresses.
2. Run full lint/test/build gate (see Testing strategy) before opening a PR.
3. Manual smoke test in a dev build (`npm run dev`) covering every nav item
   in `bottom-navbar.tsx`/`header.tsx`, since a React major/minor bump most
   commonly surfaces issues in rendering/hydration, not in business logic.
4. If `npm test` fails only on `@testing-library/react` internals (e.g. act()
   warnings), check `@testing-library/react` version compatibility with the
   new React version first — it may need a bump too, but that's a
   `devDependencies`-only, low-risk addition to this same spec if required.
